1+ Product UI

명확하고, 단순하고,
실제 서비스답게.

판매자 화면은 설문이나 실험 페이지가 아니라 실제로 운영되는 판매 신청 서비스처럼 보여야 합니다. 중립적인 표면을 기본으로 하고 중요한 행동에만 Primary 색상을 사용합니다.

02 · Components

Buttons & actions

버튼 문구는 ‘확인’보다 행동을 설명해야 합니다. Destructive 스타일은 실제 삭제나 위험한 관리자 동작에만 사용합니다.

Primary & secondary

판매자 Primary button 높이는 최소 48px을 권장합니다.

한 단계에서 가장 중요한 Primary action은 하나만 명확하게 보여줍니다.

Supporting actions

파일 교체나 삭제처럼 주 행동이 아닌 기능은 시각적 우선순위를 낮춥니다.

03 · Registration

05 · States

상태 화면도 같은 언어로

입력 오류, 제출 오류, Loading, Empty state, 신청 완료, 모집 일시중지와 종료 상태를 일관된 형태로 제공합니다.

✓판매 신청 완료

입력하신 연락처로 구매 진행 방법을 안내드릴게요.

!제출 오류

신청을 완료하지 못했습니다. 입력 내용을 확인하고 다시 시도해주세요.

06 · Quality bar

반응형과 접근성 최소 기준

최소 360px, 768px, 1280px 너비에서 확인하며 semantic HTML을 커스텀 ARIA보다 우선합니다.

Must check

작은 화면과 키보드 사용에서도 핵심 흐름이 깨지지 않아야 합니다.

✓읽을 수 있는 색 대비
✓명확한 focus 상태
✓Label과 Form control 연결
✓상태를 색상만으로 전달하지 않음
✓주요 클릭 영역은 가능하면 약 44px 이상

Avoid

현재 제품에 필요성이 검증되지 않은 표현과 작업은 제외합니다.

×gradient / glassmorphism 기반 AI Dashboard 느낌
×과도한 animation과 badge 남용
×한 화면의 여러 Primary button
×가짜 후기·거래 건수·긴급성
×판매자에게 실험/MVP임을 드러내는 문구
×검증되지 않은 다크모드·Storybook·대형 라이브러리 작업
