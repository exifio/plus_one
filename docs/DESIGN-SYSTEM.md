# DESIGN-SYSTEM.md

## 목적
판매자와 관리자 화면이 일관된 품질로 보이게 하기 위한 **최소 디자인 기준**이다.

기업용 대형 디자인 시스템이나 컴포넌트 라이브러리를 만드는 것이 목적이 아니다. 현재 제품에 필요한 규칙만 추가한다.

## 디자인 방향
레퍼런스: https://www.codeit.kr

참고할 요소:
- 명확한 정보 위계
- 크고 자신감 있는 제목
- 충분한 여백
- 짧고 직접적인 문구
- 정돈된 카드와 폼
- 명확한 Primary CTA
- 모바일과 데스크톱에서 모두 자연스러운 마감

Codeit의 브랜드, 에셋, 화면 배치, 카피를 그대로 복제하지 않는다.

판매자 화면은 설문/실험 페이지가 아니라 **실제로 운영되는 판매 신청 서비스**처럼 보여야 한다.

초기 워드마크는 텍스트 `1+`를 사용하며 별도 로고 제작은 하지 않는다.

## 기본 색상 토큰
```css
--primary: #4F46E5;
--primary-hover: #4338CA;
--primary-soft: #EEF2FF;
--text: #111827;
--text-secondary: #6B7280;
--border: #E5E7EB;
--surface: #FFFFFF;
--surface-muted: #F8FAFC;
--success: #15803D;
--warning: #B45309;
--danger: #DC2626;
```

의미 기반 토큰을 우선 사용하고 컴포넌트마다 임의의 색상을 추가하지 않는다.

전체 화면은 중립적인 배경과 표면을 기본으로 하고 중요한 행동에만 Primary 색상을 사용한다.

## Typography
권장:

`Pretendard, -apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif`

Pretendard를 별도로 설정하지 않았다면 시스템 폰트를 사용해도 된다.

- Hero/Page title: 모바일 28~32px / 데스크톱 32~40px / 700~800
- Section title: 22~28px / 700
- Card title: 18~20px / 600~700
- Body: 16px / 400~500
- Meta/Label: 14~15px / 500~600

한국어 본문 line-height는 약 1.4~1.6을 사용하고 불필요하게 많은 글자 크기 변형을 만들지 않는다.

## 간격과 형태
기본 spacing scale:

`4, 8, 12, 16, 24, 32, 40, 48, 64`

- 모바일 좌우 padding: 20px
- Field group 간격: 20~24px
- Card padding: 20~24px
- 큰 Section 간격: 40~64px
- 판매자 화면 최대 폭: 약 640~720px
- 관리자 화면 최대 폭: 약 1120~1280px
- Input/Button radius: 10~12px
- Card radius: 14~16px

강한 그림자보다 border와 spacing으로 구분하는 것을 우선한다.

## Button
- 한 단계에서 가장 중요한 Primary action은 하나만 명확하게 보여준다.
- 판매자 Primary button 높이는 최소 48px을 권장한다.
- 좁은 모바일에서는 필요한 경우 full-width를 사용한다.
- Secondary button은 뒤로가기, 취소, 파일 교체 같은 보조 행동에 사용한다.
- Destructive 스타일은 실제 삭제나 위험한 관리자 동작에만 사용한다.
- `확인`보다 `판매 신청하기`, `이미지 교체`처럼 행동을 설명하는 버튼 문구를 사용한다.

## Form
- Label을 항상 표시한다. Placeholder를 Label 대신 사용하지 않는다.
- 숫자 입력에는 `원`, `개` 같은 단위를 분명하게 표시한다.
- 오류 메시지는 해당 입력 바로 아래에 표시한다.
- 이전 단계로 돌아갔을 때 입력값을 유지한다.
- 키보드 focus 상태가 보이게 한다.
- 가능하면 기본 HTML control을 우선 사용한다.

## 선택 카드
편의점, 행사 유형, 등록 방식 선택에는 선택형 카드를 사용할 수 있다.

선택 상태는 border/outline + 연한 Primary 배경 등으로 분명하게 구분하며 **색상 하나에만 의존하지 않는다.**

## 상품 등록 방식
2단계에서는 `스크린샷으로 등록`과 `직접 입력하기` 중 하나를 선택한다.

- 두 방식의 입력 UI를 동시에 보여주지 않는다.
- 선택한 방식에 필요한 입력만 노출한다.
- 등록 방식 선택 카드는 제목과 짧은 설명으로 차이를 이해할 수 있게 한다.

### 스크린샷 등록
- 이미지 1장 선택을 기본으로 한다.
- 업로드 후 미리보기를 보여준다.
- `교체`와 `삭제`는 보조 행동으로 제공한다.
- OCR, 자동 상품 판독, 자동 보정 UI는 만들지 않는다.
- Frontend Phase에서는 실제 영구 저장보다 선택·미리보기 경험을 우선한다.

### 직접 입력
필수 입력을 최소화한다.
- 상품명
- 행사 당시 실제 결제금액
- 소비기한/유효기간은 선택

현재 MVP는 판매 수량 1개를 전제로 하므로 사용자가 수량을 별도로 선택하게 하지 않는다.

## 판매 희망금액 입력
판매자는 비율 카드가 아니라 원하는 금액을 직접 입력한다.

- 질문은 `얼마에 판매하고 싶으세요?`처럼 직접적으로 표현한다.
- 입력값 옆에 `원` 단위를 명확히 표시한다.
- 0~100% 가격 옵션, 추천 가격, 10%p 재제안 UI를 만들지 않는다.
- 행사 기준 가격이나 희망가격 비율은 필요하면 관리자 분석용으로만 사용하고 판매자 선택을 유도하지 않는다.

## Layout
### 판매자
- Mobile-first
- 하나의 주요 column
- 단순한 Header
- Desktop에서는 Form 영역을 중앙에 배치
- 현재 단계의 CTA를 사용자가 쉽게 찾을 수 있는 위치에 배치

### 관리자
- Desktop-first이지만 반응형 지원
- 빠른 정보 탐색과 밀도를 우선
- 과도한 마케팅형 여백보다 숫자 카드 + 목록/표 중심 구성

## 상태 화면
다음 상태는 일관된 형태로 제공한다.
- 입력 오류
- Form 제출 오류
- Loading
- 관리자 목록 Empty state
- 판매 신청 완료
- 모집 일시중지
- 모집 종료

신청 완료 예시:

> 판매 신청이 완료되었습니다. 입력하신 연락처로 구매 진행 방법을 안내드릴게요.

## 반응형/접근성 최소 기준
최소 다음 너비에서 확인한다.
- 360px
- 768px
- 1280px

기준:
- 읽을 수 있는 색 대비
- 명확한 focus 상태
- Label과 Form control 연결
- 상태를 색상만으로 전달하지 않음
- 주요 클릭 영역은 가능하면 약 44px 이상
- 커스텀 ARIA보다 semantic HTML을 우선
